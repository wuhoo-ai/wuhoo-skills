## 3. 四大需求映射

### 需求 1: 全量剩余赛程每日推演 🆕

**目标**: 每日新增一次全量淘汰赛推演，模拟剩余所有比赛（R32→R16→QF→SF→Final），输出冠军概率、晋级概率、预期对阵路径。

**现状缺口**:
1. ❌ 无淘汰赛赛程 JSON
2. ❌ 无小组赛→R32 种子排位模块
3. ❌ 现有 Monte Carlo 未用 v5.5 12层栈
4. ❌ 无全量推演报告生成器

### 需求 2: 淘汰赛策略保守化 🔧

**目标**: 淘汰赛 90 分钟内策略更保守、攻守更平衡、弱队更倾向防反。

**现状缺口**:
1. ⚠️ KBC 参数基于 WC1998-2022（不含 R32），48 队制下 R32 强队 vs 第三名弱队差异更大
2. ⚠️ 未考虑球队风格（防守型球队淘汰赛加成应有别于传控型）
3. ⚠️ 0 条淘汰赛专用推理规则

### 需求 3: 伤病/磨合更新 + 去除过时信息 🔧

**目标**: 全面更新伤病数据，去除过时 narrative（如葡萄牙内讧），加入团队磨合因子。

**现状缺口**:
1. ⚠️ Portugal -30 今日过期
2. ⚠️ injuries.json 3 天旧，25 队无数据
3. ⚠️ 无"团队磨合度"指标——小组赛 3 场后各队默契应有提升

### 需求 4: 近期表现权重加大 🔧

**目标**: 小组赛实际表现（而非赛前 ELO/热身赛）应在预测中占更大比重。

**现状缺口**:
1. ⚠️ ELO 更新只反映比赛结果，不反映表现质量（xG、控球率等）
2. ⚠️ 热身赛 form 仍在使用指数衰减，但小组赛表现未设专项权重
3. ⚠️ 推理引擎规则无"近期状态"维度

### 4.2 P0: 淘汰赛基础设施（Blockers）

#### 4.2.1 淘汰赛赛程 JSON (`data/knockout_schedule.json`) 🆕

基于 `references/bracket-2026.md` 的 16 场 R32 对阵槽位，生成淘汰赛赛程。

```json
{
  "version": "1.0",
  "generated": "2026-06-28",
  "stages": {
    "R32": [
      {
        "match_id": 73,
        "slot": 1,
        "date_beijing": "2026-06-30",
        "time_beijing": "03:00",
        "team_a_slot": "A2",
        "team_b_slot": "B2",
        "team_a": null,
        "team_b": null,
        "venue": "SoFi Stadium",
        "venue_city": "Los Angeles"
      },
      // ... 16 matches
    ],
    "R16": [ /* 8 matches, TBD */ ],
    "QF":   [ /* 4 matches, TBD */ ],
    "SF":   [ /* 2 matches, TBD */ ],
    "F":    [ /* 1 match, TBD */ ],
    "3rd":  [ /* 1 match, TBD */ ]
  }
}
```

**Schema 要点**:
- `team_a_slot`/`team_b_slot`: 语义槽位（如 "A2", "C1", "3rd(A/B/C/D/F)"）
- `team_a`/`team_b`: 待填（小组赛结束后根据排名填充）
- `date_beijing`: 淘汰赛日期需手动排定（或从 FIFA 官方赛程获取）

#### 4.2.2 种子排位模块 (`scripts/seed_knockout.py`) 🆕

从 `wc2026_results.json` + `wc2026_schedule.json` 读取小组赛最终排名，决定：
1. 12 组前两名 → 24 队直接进 R32
2. 8 个最优第三名 → 按 FIFA 规则分配到 R32 槽位

```python
def seed_r32_bracket(group_standings, third_place_rankings):
    """
    Returns: {slot_id: (team_a_name, team_b_name)}
    
    Algorithm:
    1. 12 group winners → assigned to slots by FIFA bracket
    2. 12 group runners-up → assigned to slots by FIFA bracket  
    3. 8 best 3rd-place → assigned via constraint-based algorithm
       (compute_third_place.py's T_SLOT_ELIGIBILITY)
    """
```

**依赖**: 读 `wc2026_results.json` 中已完成的小组赛，计算各组积分排名。

#### 4.2.3 全量推演引擎 (`scripts/bracket_simulator.py`) 🆕

升级 `wc2026_predict.py` 的 `run_monte_carlo()` 使用 v5.5 12层栈：

```python
def simulate_knockout_bracket(r32_matchups, n_sims=5000):
    """
    For each simulation:
      1. For each R32 match: call predict_single_match(knockout=True, ...)
      2. Winners advance per bracket rules
      3. Repeat through R16→QF→SF→Final
      4. Accumulate: champion%, advancement%, expected path
    Returns: MC stats + expected bracket
    """
```

**关键架构决策**: 
- 选项 A: 升级 `wc2026_predict.py` (v2.3) 使其调用 v5.5 —— **风险高，2400行代码，v2.3/v5.5 数据结构不兼容**
- 选项 B: 新建独立 `bracket_simulator.py`，直接调用 `predict_single_match(knockout=True)` —— **✅ 推荐**，零侵入，与 v5.5 wrapper 模式一致

### 4.3 P1: KBC 调优 + 淘汰赛推理规则（核心精度）

#### 4.3.1 KBC 参数更新

| 参数 | 当前值 | 新值 | 理由 |
|------|--------|------|------|
| `LAMBDA_SUPPRESSION` | 0.783 | **0.75** (R32), **0.78** (R16+), **0.82** (QF+) | R32 强弱差距更大，弱队更保守 |
| `MEAN_REVERSION` | 0.15 | **0.20** | 淘汰赛平局率目标 35%→38% |
| `UNDERDOG_BONUS[300]` | +25 ELO | **+30 ELO** | 弱队防反在淘汰赛加成更强 |
| `FAVORITE_SUPPRESSION[300]` | 0.85 | **0.82** | 强队在淘汰赛更不敢冒险 |
| 🆕 `DEFENSIVE_STYLE_BONUS` | 无 | **+10 ELO** | 防守型/防反型球队淘汰赛加成 |
| 🆕 `POSSESSION_PENALTY` | 无 | **-5 ELO** | 传控型在淘汰赛高压下效率略降 |

**实现**: 在 `knockout_calibration.py` 中增加 `round` 参数：
```python
def apply_knockout_calibration(lam_a, lam_b, elo_a, elo_b, audit=None, round='R32'):
    # Round-specific suppression
    round_suppression = {'R32': 0.75, 'R16': 0.78, 'QF': 0.82, 'SF': 0.85, 'F': 0.88}
    suppression = round_suppression.get(round, 0.78)
```
